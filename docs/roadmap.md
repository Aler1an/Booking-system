# Roadmap — Book&Study (Booking System)

## 1. Загальна мета
Створити мінімально життєздатну версію (MVP) системи бронювання навчальних слотів — **Book&Study**, яка дозволить студентам переглядати доступні часи для консультацій і бронювати їх, а адміністраторам — керувати цими слотами.  

MVP має охоплювати:
- повноцінний REST API для бронювання;
- базовий фронтенд для взаємодії користувача;
- локальну БД (SQLite або PostgreSQL);
- базову авторизацію.

## 3. Додаткові завдання (якщо буде час)
- Підключення email-сповіщень (nodemailer або інше).  
- Додавання ролей користувачів через middleware.  
- Розгортання на безкоштовному сервері (Render, Vercel).  
- Створення Docker-контейнера.

---

## 4. Acceptance Criteria (загальні)
- Усі запити мають відповідати REST-конвенції (GET, POST, PUT, DELETE).  
- Кожен endpoint має бути протестований через Postman.  
- Дані зберігаються у реляційній БД (SQLite/PostgreSQL).  
- Нефункціональні вимоги (час відповіді < 2 сек, стабільність >99%) — виконані.  
- Код проходить ESLint, тести не падають.

## 5. Розподіл ролей у команді
| Роль | Завдання |
|------|-----------|
| **Учасник 1 (Лідер)** | Архітектура проекту, бекенд, база даних, документація |
| **Учасник 2** | Авторизація, фронтенд, інтеграція API, тестування |

---

## 6. Метрики успіху
- MVP працює локально без помилок (`npm start` + `Load slots` у браузері).  
- Дані з БД відображаються у клієнті.  
- Кожен учасник створив свій **fork**, **branch**, **pull request** і **merge**.  
- Документи `business_doc.md`, `architecture_diagram.png` та `roadmap.md` є в `docs/`.

## 8. Висновок
Після завершення 4 тижнів команда отримає:
- повноцінну робочу MVP систему бронювання;
- документацію (бізнес-док, roadmap, архітектура);
- досвід роботи з GitHub через **fork → branch → PR → merge**;
- практичні навички з **Node.js, SQLite, REST API та JavaScript (frontend)**.
