# Book&Study — система бронювання навчальних слотів

## 1. Короткий опис
Book&Study — це веб-система для бронювання навчальних або консультаційних слотів у навчальному закладі.  
Студенти можуть переглядати доступні часові вікна, бронювати місця, скасовувати бронювання.  
Адміністратори керують слотами, розкладом і мають доступ до звітності.  
Система реалізована на архітектурі Client → Backend → Database з REST API та майбутнім розширенням під авторизацію й нотифікації.

---

## 2. Ролі користувачів
- Student — переглядає, бронює, скасовує власні бронювання.  
- Admin — створює часові слоти, переглядає всі бронювання, може видаляти або переносити.  

---

## 3. Основні сценарії використання
1. Як Student, хочу переглядати доступні слоти, щоб забронювати консультацію.  
2. Як Student, хочу створювати бронювання, щоб зарезервувати час.  
3. Як Student, хочу скасувати своє бронювання, якщо плани змінилися.  
4. Як Admin, хочу додавати часові вікна для бронювання.  
5. Як Admin, хочу бачити всі активні бронювання в системі.

---

## 4. Функціональні вимоги

### FR-1. Отримати список доступних слотів
AC:  
- Given: статус слота = “available”  
- When: GET /slots?date=YYYY-MM-DD  
- Then: 200 OK + JSON масив слотів  
- Errors: 400 (invalid date), 500 (DB error)

### FR-2. Створити бронювання
AC:  
- Given: Student авторизований, слот “available”  
- When: POST /bookings з {slotId, userId}  
- Then: 201 Created + дані бронювання  
- Errors: 401 (unauthorized), 404 (slot not found), 409 (already booked)

### FR-3. Скасувати бронювання
AC:  
- Given: бронювання існує та належить Student  
- When: DELETE /bookings/{id}  
- Then: 200 OK + статус “cancelled”  
- Errors: 401 (unauthorized), 403 (not owner), 404 (not found)

### FR-4. Додати новий слот (Admin)
AC:  
- Given: роль = Admin  
- When: POST /slots з {date, startTime, endTime}  
- Then: 201 Created + слот у базі  
- Errors: 400 (invalid data), 401 (unauthorized)

## 5. Нефункціональні вимоги (NFR)

| Категорія | Вимога | Метрика / Інструмент |
|------------|--------|-----------------------|
| Швидкодія (API) | p95 для GET /slots ≤ 200 мс при 50 RPS | Tracing / Prometheus |

| Безпека | TLS ≥ 1.2, rate-limit 10 req/min/IP на /auth/* | OWASP checklist |
| Відновлення | RTO ≤ 15 хв, RPO ≤ 5 хв, щогодинні бекапи | PostgreSQL backup jobs |
| Масштабованість | Автоматичне масштабування при CPU > 60% | Horizontal scaling |
| Спостережуваність | 100% запитів із request_id; <0.5% 5xx | Logs + Metrics Dashboard |

---

## 6. Обмеження
- Система не реалізує оплату за бронювання.  
- Відсутні push-сповіщення (тільки email — у майбутньому).  
- Адміністратор не має аналітичних звітів (у MVP-версії).

---

## 7. Ризики дизайну та запобігання
| Категорія | Ризик | Як уникнути |
|------------|-------|--------------|
| Продуктивність | Перевантаження БД при фільтрації | Індекси, пагінація |
| Надійність | Падіння сервера | Health-checks, автоrestart |
| Перевантаження API | Занадто багато запитів | Rate limit + cache |
| Кеш | Дані не оновлюються | TTL + cache invalidation |
| Безпека | Несанкціонований доступ | JWT, HTTPS, рольова модель |
| Відновлення | Втрата даних | Бекапи, реплікація БД |
